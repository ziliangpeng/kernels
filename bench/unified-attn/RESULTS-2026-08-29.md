## Suites

- **sweep** (fp8kv): controlled 2-factor sweep — fixed ~4k query-token budget, vary phase mix
  (pure prefill → decode-dominated → pure decode) and context length (8k→64k)
- **random** (fp8kv): 8 randomized production-like batches — heavy-tail prefill lengths,
  heavy-tail KV lengths (128–65k), mixed phase ratios, seeded draw

### Skew isolation experiment (256 dec, fp8kv)
| KV distribution | aiter ms | vllm ms | ratio |
|---|---|---|---|
| uniform 8k each (2.1GB total) | 0.217 | 0.627 | 2.9× |
| skewed (128–65k, 2.8GB total) | 0.366 | 3.891 | **10.6×** |
| uniform, same bytes as skewed (11k each) | 0.251 | 0.837 | 3.3× |

→ The 10× random-batch gaps come from **length skew**, not total bytes: same total KV, uniform
distribution = 3.3×; skewed = 10.6×. vLLM's fixed tile config degrades on stragglers
(longest sequences dominate the tail); aiter's adaptive config absorbs it.

## Key findings (cumulative)

1. **AITER wins the overwhelming majority of shapes on gfx942**: 1.05×–10.6×, correctness-gated.
2. **Skew is the amplifier**: heavy-tail KV length distribution widens the gap to 10×+ (uniform same-bytes = 3.3×). Real production traffic IS heavy-tailed → the aiter gap in production is likely near the upper end.
3. **Aiter can LOSE**: draw #6 (192 dec, 3 small prefills, tight uniform-ish lengths) → aiter 0.90×. The 3D/split-KV path config has shapes where it under-performs 2D-oriented work. Not dominant, but real — good reason for end-to-end A/B before production flip.
4. Long context (64k) works on both — no OutOfResources at d=128, blk=32.
5. Phase mix matters less than length skew: prefill-heavy vs decode-heavy at same budget = 1.9×–5.1× (vllm side varies more than aiter side: aiter stays 0.70–0.80ms across all mixed cases — robust; vllm swings 1.5→3.7ms).

## GOTCHA (bit us, will bite again)
**vLLM standalone `unified_attention` silently mis-quantizes fp8 KV without explicit `kv_quant_mode=KVQuantMode.FP8_PER_TENSOR`** — default NONE casts fp8→bf16 without dequant → 49× wrong, no error. Backend impl passes it from metadata (production safe). Direct kernel benches MUST pass it. Correctness gate caught it; never bench un-validated.

## Caveats
- Random ±0.3 tensors; single GPU; no CUDA graph; clocks not locked (sequential A/B mitigates, cross-validation would be better).
- Kernel-level ratios ≠ end-to-end gains (attention is a fraction of model step time).
