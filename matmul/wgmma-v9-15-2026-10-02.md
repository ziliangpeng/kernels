# v9.15 worklog — 256x128 tall tile, 4 consumer WGs (2026-10-02)

## Design

Fix for v9_14's issue-limit (tensor 69/mem 71, 2 consumer warps/scheduler
insufficient to hide the issue path). v9_15 doubles the tile along M:

- CTA tile 256x128, 640 threads (1 producer WG + 4 consumer WGs), each
  consumer m64n128k16 (4 x m64 = 256 rows). 4 consumer warps/scheduler.
- STAGES=4 (192KB): A [4][256x128B] 32KB/stage + B [4][128x128B] 16KB/stage.
- cluster 2 along M, B split-issue multicast unchanged (rank r issues n-box r).
- Ledger: full count 2 (expect_tx 40KB local + 8KB peer remote = 48KB/lap);
  free count 8 (both CTAs' 4 consumer WGs, ct==0 arrives local + remote).
- L2-read AI per cluster: 80KB / 8.39M FLOP = 104.6 FLOP/B (vs 87.4 for the
  128x256 no-cluster design; 20% less L2 read per FLOP).
- Epilogue: stage C 256x128 f32 (128KB) over drained pipeline; 4 TMA stores.

## NCU @8192

- tensor pipe 84.4% (v9_14: 69.4) — 4 warps/scheduler recovered most of the
  issue-hiding gap. Memory 70.7%, L2 70.6%.
- WarpState: barrier 6.25, wait 2.33, long_scoreboard 1.42, gmma 1.02,
  selected 1.00.
- Verdict: closer but still mbarrier-paced (barrier+wait dominate). The
  multicast path costs issue slots + barrier traffic vs v9_11's simpler
  2-consumer structure; tile-shape gain (L2 AI 104.6 vs 87.4) is real but
  the memory pipe at 70% is still not the binding constraint, so the L2
  saving does not convert to time.

## Conclusion of the multicast arc (three strikes)

- v9_12/13 @128x256: multicast saves L2 reads, but L2 was never the
  bottleneck there (58-68%) — flat.
- v9_14 @128x128 (CUTLASS winner geometry): issue-limited at 69/71 — the
  m64n128 macro halves work per instruction; never reaches the L2 bound.
- v9_15 @256x128 tall: recovers warp capacity (84.4% tensor) but the
  simpler v9_11 structure (128x256, no cluster, m64n256) still wins by 9%
  — its m64n256 macro does 2x the work per instruction with half the
  barrier handshakes.

Design-point verdict: for a hand-written 4-stage pipeline at this
sophistication, 128x256 + m64n256k16 + no cluster remains the local optimum.
CUTLASS's 743T at 128x128 presumably buys its win with a deeper machinery
(2-stage mainloop pipelining across k, warp-specialized issue, or persistent
scheduling) that is beyond this ladder's current scope — reading its source
remains the honest next step if we want more.
