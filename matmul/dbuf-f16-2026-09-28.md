# dbuf_f16 — warptile + cp.async double buffering, FP16 storage (2026-09-28)

Rung 12 of the 16-bit ladder. FP16 port of matmul_warptile_dbuf.cu with two
layout changes forced by cp.async's 4/8/16B granularity:

- A tile: NATURAL layout As[2][BM][BK+2] (FP32 used transposed As[2][BK][BM];
  a 2B half can't form aligned 4B chunks in transposed order along k). Loads
  are 4B = 2 halves along k; +2-half pad makes the row stride odd in 4B words
  → bank-conflict-free k-walks.
- B tile: Bs[2][BK][BN], 16B = 8-half chunks along N (same vectorization
  factor as FP32's float4).

## Bugs found & fixed on the way

1. **B src double-counted blockCol*BN** (port bug; FP32 original computes src
   WITHOUT it because B is pre-advanced at kernel entry). compute-sanitizer
   caught a 16B OOB read at N=512; N=4096 passed silently by adjacency luck.
2. usleep needed <unistd.h>; masked for two rounds by rsync -a preserving
   mtimes → build script's -nt skip check thought the TU was up-to-date
   ("BUILD OK" with a stale binary). Fix: rsync --checksum + strings-verify
   new code actually landed in the binary.
3. dbuf16_autotune dispatched after matmul_op's own allocations → 80GB OOM
   at N=4096. Moved to early dispatch.
4. Out-of-line template member defs needed `using T = typename Traits::T`.
5. Config 16 (64,64,16,64,64,...) violated warp-cover static_assert —
   the static_assert caught it at compile time (exactly what it's for).

## Results (job 219328, node h100-0-18, 16 configs)

- Default config (128,256,8,64,64,2,8,4,256): 33.47T (verify PASS 5e-3, N=512)
- **Tuned winner (128,256,16,64,64,2,8,4,256): 34.16T** — FP16 prefers BK=16
  (FP32 winner config is BK=8 → dtype-dependent optimum again)
- vs FP32 dbuf tuned 37.60T: **0.908x**
- vs FP16 ladder: vec tuned 36.47 > dbuf_f16 34.16 > warptile_f16 32.69
  (cp.async pipeline buys +4.5% over plain warptile on FP16, but pure load
  vectorization still wins — consistent with the traffic-bound FP16 model)

Caveat: both dbuf numbers (FP32 37.60, FP16 34.16) come from multi-instance
sweep builds; the ratio 0.908x is same-harness-class. Single-instance ABAB
duel pending if we want production-grade numbers.
