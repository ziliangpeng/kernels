# WGMMA v4 — 128x128 CTA, 4 warpgroups (2026-09-28)

## Result (job 219584, node h100-0-3)

**135.82T @ N=4096, verify PASSED (7.67e-05)** — CTA tile 128x128, 512
threads = 4 warpgroups in a 2x2 quadrant split, each running the same
sweep-verified m64n64k16 macro. v2 (64x64 single warpgroup): 104.36T.

## Design

- Quadrant layout: a 64x16 quadrant's atoms span 2048B (2 K-atoms x
  LBO=1024). Rows 64-127 form the second quadrant at +2048 — the v4 bug was
  using +1024 (confusing the 64-row atom-grid periodicity with the quadrant
  footprint).
- Quadrant descriptor = base + wgM/wgN * 2048, SAME LBO=1024/SBO=128 —
  one layout works for all 4 warpgroups, no per-quadrant re-staging.
- Pipeline: prologue loads tile 0; steady state issues wgmma on buf, then
  (wait_group 1 + syncthreads) loads tile k+1 into buf^1. Cross-warpgroup
  safety: wait_group 1 is per-wg, the following __syncthreads() covers all.

## Measured roofline check

AI = 2*128*128*16 / ((128+128)*16*2) = 64 FLOP/B. At 3.35TB/s HBM:
~230T cap. Measured 135.8T = 59% of cap — so v4 is NOT purely HBM-bound.
Gap suspects: (a) GMEM loads via regular LDG (no cp.async/TMA) — latency
exposed at only 2-deep buffering; (b) per-step __syncthreads x2 (512
threads); (c) L2 hit rate for A-tiles shared by 4 column-CTAs.
