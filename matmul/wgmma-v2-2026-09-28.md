## The bug chain (8 rounds, each a lesson)

1. SBO=1024/2048 (LeetCUDA swizzle constants pasted into no-swizzle) →
   illegal access. Correct: 128.
2. Epilogue mapping invented (8 regs/16-col groups) → rel 1.00. Correct PTX
   m64nN: 4 regs per 8-col group (row, row+8 × col, col+1).
3. Row-pitch-32B SMEM layout not expressible by no-swizzle GMMA → rel 0.28.
   Correct: canonical interleave (core matrix 8x8 halfs = 128B contiguous;
   atom (mi,ki) at mi*128 + ki*1024; LBO=1024, SBO=128).
4. My own multi-replace no-ops left a Frankenstein file (m64n64 asm + 64
   accs + n128 layout) → "n64 test" was invalid. Lesson: multi-segment edits
   via write_file/patch only; verify file state with grep before building.
5. 243-combo brute-force descriptor sweep (one combo per process — sticky
   context poisons everything after an illegal access) + CPU verify found
   the ONLY passing combo: L0 / LBO=1024 / SBO=128. Empiricism beats
   spec-reading when the spec is CuTe notation.
6. K-loop sweep test "failed" — but my verify compared against the k=0..15
   partial reference. Kernel was right; the TEST was wrong.
7. transposeB unit test: OK (not the bug).
8. **fence.proxy.async.shared::cta** — THE root cause of the remaining
   mismatch. PTX requires an async-proxy fence between generic-proxy SMEM
   writes and wgmma's async-proxy reads; __syncthreads() does NOT order
   across proxies. The element-wise sweep kernel passed by luck (compiler
   scheduling); uint4 stores in the main kernel exposed it. Every CUTLASS
   wgmma kernel has this fence — now we know why.
