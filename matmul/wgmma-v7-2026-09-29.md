## Result (job 220205, node h100-0-3)

**162.73T @ N=4096, verify PASSED (6.65e-05)** — vs v6 164.83T (h100-0-26):
FLAT (node spread ~7%). Bigger tile (AI 64 -> 85, roofline 230 -> ~290T)

## Interpretation (the valuable negative result)

If v6 were bandwidth-bound, v7's higher arithmetic intensity would have
gained ~15-25%. It didn't -> v6's remaining 28% gap to its HBM roofline is
NOT bandwidth. Remaining suspects, in order:
1. 2x __syncthreads per K-step (256 threads x 256 steps).
2. cp.async issue rate: 3 copies/thread/stage (1 A + 2 B) x 256 threads.
3. wgmma wait_group<1> serialization: only 1 wgmma in flight per wg.
4. Only 2 CTAs' worth of independent work per SM (occupancy for latency).

## Bugs fixed en route (same root cause: staging granularity changed, offset
constants didn't)

1. loffB kept a lchunk*4096 term after B staging switched to brow=tid with
   explicit chunks -> odd-tid rows landed +4096 off (maxrel 1.00).
2. B k-chunk-2 offset was +1024 (v2-era A-layout residue); correct = +LBO
   = +4096 for m64n256 (32 n-atoms x 128B) -> maxrel 0.597 -> PASS.

Rule: when staging granularity changes, RE-DERIVE every offset constant
from the layout formula; never reuse constants across versions.
