1D blocktile 可视化

~/code/kernels/matmul · matmul_1d_blocktile.cu · H100 · FP32 · 第 4 课

1. 思路：一个 thread 算一列上的 8 个输出

smem kernel 的问题：从 smem 读出来的 A 和 B，在每个 lane 里只做 1 次乘加就扔掉，每次 FMA 要读 2 次 smem，瓶颈从 global memory 转到了 smem。

1D blocktile 让每个 thread 算 C 同一列上连续 8 个元素（TM = 8）。这 8 个输出在同一个 k 上乘的是同一个 B[k][c]：

C[r+0][c] += A[r+0][k] * B[k][c]
C[r+1][c] += A[r+1][k] * B[k][c]
...
C[r+7][c] += A[r+7][k] * B[k][c]   ← 8 行都乘同一个 B[k][c]

所以 B 只从 smem 读一次，放进寄存器 tmpB，连续用 8 次。这就是 register tiling（也叫 register blocking、thread coarsening）：cuBLAS、CUTLASS、CPU BLAS 的 microkernel 都靠它。"1D"只是教学用的过渡形式，下一课的 2D 才是标准形式。

层级存什么谁共享引入于
global（HBM / L2）整个 A、B、C所有 block一开始
smemA、B 的 tile一个 block第 3 课
寄存器tmpB 和 8 个累加值一个 thread本课

2. 参数

参数值含义
BM × BN64 × 64一个 block 负责 C 的 64×64
BK8每轮沿 K 搬 8 列 A、8 行 B
TM8每个 thread 算 8 个输出
thread 数64/8 × 64 = 512As、Bs 各 512 格 → 每个 thread 正好搬 1 个 A、1 个 B，所以 BK 取 8
smem(512+512) × 4B = 4KB比上一课的 8KB 还少

3. 代码（逐行注释）

__shared__ float As[64][8];
__shared__ float Bs[8][64];

const int threadCol = threadIdx.x % 64;   // 一维 block，0..511
const int threadRow = threadIdx.x / 64;   // 0..7 → 负责 C 第 threadRow*8 .. +7 行
// warp 视角：32 个连续 tid → threadRow 相同，threadCol 连续 32 个

A += blockRow * 64 * N;                   // 指针挪到这个 block 的起点
B += blockCol * 64;
C += blockRow * 64 * N + blockCol * 64;

float threadResults[8] = {0.0f};          // 下标编译期可知 → 编译器放进 8 个寄存器

// 搬运用另一套映射（和计算的映射无关，中间有 __syncthreads 隔开）
const int innerRowA = threadIdx.x / 8,  innerColA = threadIdx.x % 8;    // As: 64 行 × 8 列
const int innerRowB = threadIdx.x / 64, innerColB = threadIdx.x % 64;   // Bs: 8 行 × 64 列

for (int tileIdx = 0; tileIdx < N; tileIdx += 8) {
    As[innerRowA][innerColA] = A[innerRowA * N + innerColA];   // warp：4 行 × 32B，每个 sector 用满
    Bs[innerRowB][innerColB] = B[innerRowB * N + innerColB];   // warp：连续 128B，coalesced
    __syncthreads();
    A += 8;  B += 8 * N;                                        // A 右移 8 列，B 下移 8 行

    for (int dotIdx = 0; dotIdx < 8; dotIdx++) {
        float tmpB = Bs[dotIdx][threadCol];                     // 读 1 次 B → 寄存器
        for (int resIdx = 0; resIdx < 8; resIdx++)
            threadResults[resIdx] +=
                As[threadRow * 8 + resIdx][dotIdx] * tmpB;      // 读 1 次 A，做 1 次 FMA
    }
    __syncthreads();
}
for (int resIdx = 0; resIdx < 8; resIdx++)                     // 写回：warp 每次写一行连续 32 个
    C[(threadRow * 8 + resIdx) * N + threadCol] = threadResults[resIdx];

5. 算账

smem kernel1D blocktile
每个输出每个 k 的 smem 读29/8
每 256 次 warp-FMA 的 smem 访问169
每搬 1 个 float 进 smem 能做的 FMA（BM·BN/(BM+BN)）1632

smem 访问约少 1.78 倍；block tile 从 32×32 变成 64×64，global 访问也减半。另外，固定 resIdx 时 A 跨 8 个 dotIdx 读的是 As[r][0..7] 连续 8 个 float，完全展开后编译器可能合并成 2 条 LDS.128。这一点没看过 SASS，是推测。

为什么只到 17.6T（FP32 峰值约 67T）——推测，未测：每 8 个 k 就要两次 __syncthreads，两次 sync 之间每个 thread 只有 64 次 FMA；搬运和计算串行，global 延迟没被隐藏；A 仍是 8 次读喂 8 次 FMA（下一课 2D blocktile 让 A、B 都进寄存器复用）。

7. 仓库文档里的问题（未修改）

  • matmul_1d_blocktile.h 的 "Expected ~36.5% of cuBLAS (2.8x over smem)" 是 siboehm 在 A6000 上的数字；本机是 33.8%、1.95×。
  • 同一文件说提升来自 "reducing thread management overhead"——主因其实是 smem 读减少和寄存器复用。
  • worklog.md:268 说 "One A column held in registers"，但代码里进寄存器的是 tmpB（B），A 每次从 smem 读。
  • blockDim 参数仍未使用。

8. 要点

  • 省掉的是 smem → 寄存器的 LDS：B 读一次进 tmpB，复用 8 次。带宽和指令发射槽都省了。
  • 同一条原则用了第二次：内存层级的每一层都让数据读一次、用多次。HBM→smem 是第 3 课，smem→寄存器是本课。
  • 搬运和计算可以用不同的 thread 映射，靠 __syncthreads 隔开。
  • 局部数组只有在下标编译期可知时才会进寄存器。
