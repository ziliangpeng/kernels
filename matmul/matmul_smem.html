Shared memory tiling 可视化

~/code/kernels/matmul · matmul_smem.cu · H100 · FP32 · 第 3 课

1. 思路：让整个 block 共用一份数据

在 coalesced kernel 里，一个 32×32 的 block 负责 C 的一个 32×32 小方块。这 32 行都要用 A 的同样 32 行，这 32 列都要用 B 的同样 32 列，可是每个 thread 都自己从 global memory 把整行、整列读一遍。同一个 A[row][k] 被 32 个 thread 各发一次 load。

shared memory（smem）是 SM 上的片上 SRAM（和 L1 是同一块物理存储），由程序员自己管理，同一个 block 的所有 thread 都能读写，延迟只有二三十个 cycle。smem tiling 的做法：

  1. 整个 block 一起，把 A 的一个 32×32 tile 和 B 的一个 32×32 tile 从 global memory 搬进 smem，每个 thread 只搬 1 个 A 元素和 1 个 B 元素。
  2. __syncthreads() 等所有人搬完。
  3. 每个 thread 在 smem 里做 32 次乘加。
  4. __syncthreads() 等所有人算完，然后沿 K 方向搬下一块。

2. 代码（逐行注释）

#define SMEM_TILE 32
__global__ void matmulSmemKernel(const float *A, const float *B, float *C, int N) {
    __shared__ float As[32][32];   // 4KB，整个 block 只有一份
    __shared__ float Bs[32][32];   // 4KB

    int tx = threadIdx.x, ty = threadIdx.y;   // block 是 32×32：一个 warp = 同一个 ty，tx 取 0..31
    int row = blockIdx.y * 32 + ty;           // 这个 thread 负责的 C 元素
    int col = blockIdx.x * 32 + tx;
    float sum = 0.0f;

    for (int tileIdx = 0; tileIdx < N; tileIdx += 32) {   // N=4096 时共 128 块
        // 阶段一：每个 thread 搬 1 个 A、1 个 B（越界填 0）
        As[ty][tx] = A[row * N + (tileIdx + tx)];   // warp 内 tx 连续 → 128B 连续，coalesced
        Bs[ty][tx] = B[(tileIdx + ty) * N + col];   // 同上
        __syncthreads();                            // RAW：等所有人写完再读

        // 阶段二：全部在 smem 里算
        #pragma unroll
        for (int k = 0; k < 32; k++)
            sum += As[ty][k] * Bs[k][tx];
        __syncthreads();                            // WAR：等所有人读完，下一轮才能覆盖
    }
    C[row * N + col] = sum;
}
// launch：dim3 threads(32, 32)；grid = (N/32, N/32)。-b 参数被忽略。

4. 两个 __syncthreads()

位置防的是什么如果删掉
搬完之后、计算之前RAW（read-after-write）：thread (3,5) 要读的 As[3][0..31] 由 warp 3 的 32 个 thread 写，Bs[0..31][5] 由 32 个不同的 warp 写可能读到上一块的旧值或还没写进去的值
计算之后、下一轮搬之前WAR（write-after-read）：快的 warp 进入下一轮会覆盖 As/Bs慢的 warp 读到被覆盖的数据；结果时对时错，很难查

5. 两种视角看 smem 读

代码 sum += As[ty][k] * Bs[k][tx] 写的是单个 thread：A 沿第 ty 行往右走，B 沿第 tx 列往下走。但硬件按整个 warp执行（同一个 ty，tx = 0..31）：

读32 个 lane 的地址结果
As[ty][k]全部相同broadcast，1 次 smem 访问只拿到 1 个有用的 float
Bs[k][tx]连续 32 个 float（第 k 行整行）32 个 bank 各一个，无冲突，1 次访问拿到 32 个

把 32 个 thread 各自"往下走的一列"并排放，每个 k 上看到的就是 Bs 的一整行。

6. 算账

每个 thread（N=4096）coalescedsmem tiling
global load2N = 81922·N/32 = 256
smem load08192
__syncthreads0256

global load 少了 32 倍，速度却只提高 1.59 倍：瓶颈换成了 smem。每个 warp 每个 k 要 2 次 smem 访问（A broadcast 一次，B 一行一次）换 32 次 FMA。一个 SM 每个 cycle 大约服务 1 次 smem 访问（32 bank × 4B），所以每个 cycle 最多约 16 次 FMA，而 FP32 单元每个 cycle 能做 128 次，只用到约 1/8，约 8.4T。如果编译器把 As[ty][k..k+3] 合并成 LDS.128，上限大约 13T。实测 9.0T 落在区间内。这是推算，还没有用 SASS 或 ncu 验证。

8. 仓库文档里的问题（未修改）

  • worklog.md:134 说 As[ty][k] "ty 在 thread 间变化、步长 32 → 不同 bank"。实际上一个 warp 的 ty 相同，是 broadcast；而且若 ty 真的变化，步长 32 个 float 会落在同一个 bank，是 32-way conflict。结论（无冲突）碰巧对，推理错。
  • MatmulSmem 收 blockDim 参数但不用，-b 无效。
  • matmul_smem.h 的 "Expected ~12.8% of cuBLAS" 是 siboehm 在 A6000 上的数字，不是本机实测。

9. 要点

  • smem 是 block 共享、程序员管理的片上存储；tiling 让每个 global 元素只读一次、被 32 个 thread 共用。
  • 两个 __syncthreads 分别防 RAW 和 WAR，缺一不可。
  • 瓶颈从 global load 转到 smem：每次 FMA 仍要读 2 次 smem，A 还是 broadcast。下一课 1D blocktile 让一个 thread 算多个输出，一次 smem 读喂多次 FMA。
