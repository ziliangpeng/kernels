# WGMMA v8 — warp specialization + mbarrier pipeline (2026-09-29)

## Result (job 220430, node h100-0-7)

**150.52T @ N=4096, verify PASSED (7.75e-05)** — vs v6/v7 ~163T
(cross-node; v8 is correctness-first with consumer wgmma_wait<0> — the
wgmma-overlap was deliberately sacrificed to land a correct kernel first).

## Design

Producer wg (128 threads) issues all cp.async staging; 2 consumer wgs run
m64n256k16 on 64x256 strips. mbarrier full[s] (count 128) / free[s] (count
2) pipeline; ZERO steady-state __syncthreads. TMA deferred to v9: dense-box
TMA cannot express the no-swizzle interleave without swizzle-mode re-derivation.

## Bug chain (4 rounds — every one a first lesson in warp-spec territory)

1. Deadlock #1 (mbarrier phases): phases complete once per CYCLE (STAGES
   laps), not per lap. Hand-flipped parity inverted every 3 laps at lap 3.
   Fix: derive parity from lap index — consumer full parity (c&1), producer
   free parity ((c-1)&1).
2. nvcc: try_wait parity param must be by value (non-const ref can't bind
   temporaries).
3. Deadlock #2 (the original): __syncthreads() INSIDE the producer branch —
   block barriers need all 384 threads; consumers never arrive. Fix: init
   by tid==0 + one block-wide barrier before the role split.
4. Verify FAIL 1.00: producer's pt/2 mapping staged only A rows 0..63 (128
   of 256 16B chunks); rows 64..127 never loaded. Fix: each producer thread
   loads one full row (both k-chunks).

## v8.1 addendum (job 221145, node h100-0-0)

145.78T verify PASS — overlap via wait<1> release LOST ~5T vs the
serialized v8 (150.52T). Interpretation: the consumer spin on
mbarrier/try_wait + wgmma_wait occupies SMSP issue slots that wgmma and the
producer need; with only 2 CTAs' occupancy the spin steals more than the
overlap returns. Same lesson family as the Fable issue-slot model: extra
instructions only pay when there is slack. Verdict: cp.async-based warp
specialization on this shape is a dead end — the remaining feeding lever is
TMA (one bulk copy per tile, near-zero issue cost), which is v9.
