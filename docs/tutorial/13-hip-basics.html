1. What is HIP?

HIP (Heterogeneous-Compute Interface for Portability) is AMD's CUDA equivalent. It's a C++ programming model for AMD GPUs, with nearly identical syntax to CUDA. The key insight: HIP is designed to be a drop-in replacement for CUDA — most CUDA code can be converted automatically.

2. hipify — automatic conversion

# hipify-perl converts CUDA → HIP automatically
hipify-perl vector_add.cu > vector_add.hip

# Or use hipify-clang for more accurate conversion
hipify-clang vector_add.cu -o vector_add.hip

# The output is nearly identical — just cuda→hip renames
~95% of CUDA code converts automatically. The main manual changes are: warp size (32→64), some intrinsics (__shfl variants), and architecture-specific features. The vector_add kernel from chapter 01 needs zero changes.

3. CUDA → HIP API mapping

// CUDA                              // HIP
cudaMalloc(&d_a, bytes);        →   hipMalloc(&d_a, bytes);
cudaMemcpy(d, h, n, H2D);      →   hipMemcpy(d, h, n, hipMemcpyHostToDevice);
cudaDeviceSynchronize();        →   hipDeviceSynchronize();
cudaFree(d_a);                  →   hipFree(d_a);
cudaGetLastError();             →   hipGetLastError();

// Kernel launch — IDENTICAL syntax
my_kernel<<<grid, block>>>(args);   // works in both CUDA and HIP

4. Compiling with hipcc

# Compile HIP code
hipcc -o vector_add vector_add.hip

# With architecture flag for MI300X (gfx942)
hipcc -O3 --offload-arch=gfx942 -o vector_add vector_add.hip

# For MI350X (gfx950)
hipcc -O3 --offload-arch=gfx950 -o vector_add vector_add.hip
Architecture flags matter. gfx942 = MI300X/MI325X, gfx950 = MI350X/MI355X. The wrong flag means the code won't run or will fall back to generic compilation (missing native FP8/MXFP4 support).

🎯 Chapter 13 Summary

HIP is AMD's CUDA equivalent with nearly identical syntax. hipify-perl converts CUDA→HIP automatically (~95% of code). Key API renames: cuda*→hip*, nvcc→hipcc. Kernel launch syntax (<<<grid,block>>>) is identical. Main difference: wavefront size = 64 (vs warp = 32). Architecture flags: gfx942 (MI300X), gfx950 (MI350X).

🧪 Quick Check

You have a CUDA kernel using threadIdx.x and __syncthreads(). What changes are needed for HIP?

None. threadIdx and __syncthreads() work identically in HIP. Just run hipify-perl to rename cuda* to hip*, then compile with hipcc. The only thing to watch out for is the warp size difference (32 vs 64) if you use warp-level primitives like __shfl_sync.
