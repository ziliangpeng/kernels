1. What is Triton?

Triton is a Python-based GPU programming language. It gives you CUDA-level performance without writing CUDA C++. Instead of managing threads, warps, and shared memory manually, you write block-level programs and Triton handles the low-level optimization automatically.

CUDA C++Triton
LanguageC++Python
AbstractionPer-threadPer-block
SMEM managementManualAutomatic
CoalescingManualAutomatic
Tensor coresManual (wmma)Automatic (emits MFMA/WMMA)
PerformancePeak (with effort)~90% of peak (with ease)
GPU supportNVIDIA onlyNVIDIA + AMD
Why Triton matters: FlashAttention, vLLM, and SGLang all use Triton kernels. It's the dominant way to write custom GPU kernels for ML today. OpenAI, Meta, AMD, and the entire open-source ML ecosystem have standardized on it.

2. First Triton kernel — vector add

import triton
import triton.language as tl
import torch

# @triton.jit = "this is a GPU kernel"
@triton.jit
def vector_add(x_ptr, y_ptr, z_ptr, n,
                  BLOCK_SIZE: tl.constexpr):
    # Get this program's ID (like blockIdx)
    pid = tl.program_id(0)

    # Compute the range of elements this program handles
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)

    # Bounds check
    mask = offsets < n

    # Load from global memory (with masking)
    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)

    # Compute
    z = x + y

    # Store to global memory
    tl.store(z_ptr + offsets, z, mask=mask)

# Launch from Python
def launch(x, y):
    z = torch.empty_like(x)
    n = x.numel()
    grid = (triton.cdiv(n, 1024),)  # number of programs
    vector_add[grid](x, y, z, n, BLOCK_SIZE=1024)
    return z

3. Programming model — programs not threads

CUDA vs Triton mental model: CUDA: You think about THREADS. "Thread 0 loads element 0, thread 1 loads element 1..." You manage threadIdx, blockIdx, __syncthreads, shared memory. Triton: You think about PROGRAMS (≈ blocks). "Program 0 loads elements [0:1024], program 1 loads [1024:2048]..." Triton handles threads, coalescing, SMEM, and synchronization. The key abstraction: tl.arange(0, BLOCK_SIZE) creates a vector of indices. Operations on it are SIMT — applied to all elements in parallel, like NumPy but running on the GPU as a single block.

4. Block-level operations

# tl.arange — create index vectors (like np.arange)
offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)

# tl.load / tl.store — memory I/O with masking
x = tl.load(ptr + offsets, mask=offsets < n)
tl.store(ptr + offsets, result, mask=offsets < n)

# Element-wise ops — automatic SIMD
z = x * 2.0 + y

# Reductions — automatic tree reduction
total = tl.sum(x)           # sum all elements
max_val = tl.max(x, axis=0)  # max along axis

# tl.dot — matrix multiply (uses tensor cores automatically!)
c = tl.dot(a, b)  # a: (M, K), b: (K, N) → c: (M, N)

# tl.cdiv — ceiling division
grid = (tl.cdiv(n, BLOCK_SIZE),)
tl.dot automatically uses tensor cores. If the inputs are FP16/BF16, Triton emits WMMA (NVIDIA) or MFMA (AMD) instructions. You get tensor core performance without writing any hardware-specific code. This is Triton's biggest advantage.

🎯 Chapter 17 Summary

Triton is Python-based GPU programming with block-level abstraction. You write @triton.jit kernels using tl.program_id (like blockIdx), tl.arange (index vectors), tl.load/store (memory I/O with masking), and tl.dot (auto tensor cores). No manual SMEM, coalescing, or synchronization — Triton handles it. Supports NVIDIA + AMD. FlashAttention, vLLM, SGLang all use Triton.

🧪 Quick Check

In Triton, how do you handle arrays that aren't a multiple of BLOCK_SIZE?

Use masking. Create offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE), then compute mask = offsets < n. Pass mask=mask to tl.load and tl.store. Out-of-bounds elements get zero on load and are skipped on store. This is the Triton equivalent of if (tid < n) in CUDA — but vectorized over the whole block.
