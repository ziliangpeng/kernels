1. rocm-smi — GPU monitoring

# Basic GPU info (like nvidia-smi)
rocm-smi

# Show only utilization and memory
rocm-smi --showuse --showmeminfo

# Output:
# GPU 0: MI300X
#   Temperature: 55°C
#   Power: 280W / 750W
#   Memory: 45.2GB / 192GB
#   GPU util: 87%

2. rocprof — profiling

# Profile a HIP application
rocprof -o profile.txt ./my_kernel

# With specific counters
rocprof --stats ./my_kernel

# Key metrics:
#   TOTAL_TIME — kernel duration
#   GRBM_COUNT — number of waves executed
#   L2_CACHE_HIT_RATE — cache effectiveness
#   FETCH_INSTRUCTIONS — instruction count

3. omniperf — deep analysis

omniperf is AMD's equivalent of Nsight Compute — a deep, per-kernel analysis tool with roofline modeling.

# Profile with omniperf
omniperf profile -n my_kernel -- ./my_app

# Analyze results
omniperf analyze --kernel-name gemm_tiled

# Key outputs:
#   Roofline plot (is your kernel memory or compute bound?)
#   Occupancy analysis
#   Register/SMEM usage
#   Wavefront count and divergence
#   Memory access patterns (coalescing)
Omniperf roofline analysis: Achieved TFLOPS ↑ │ ╭─── your kernel is here (compute-bound) │ ╱ │ ╱ ← compute ceiling │ ╱ │ ╱ │ ╱ ╭─── your kernel is here (memory-bound) │ ╱ ╱ │ ╱ ╱ │ ╱╱ ← memory bandwidth ceiling │ ╱ └──────────→ Arithmetic intensity Omniperf shows exactly where your kernel sits on the roofline, and which hardware counter is the bottleneck.

4. hipify tools

# hipify-perl — simple text replacement
hipify-perl input.cu > output.hip

# hipify-clang — more accurate, uses Clang AST
hipify-clang input.cu -o output.hip

# Check what was changed
hipify-perl input.cu --diff > changes.diff
Always check the hipify diff. While 95% is automatic, some changes need manual review — especially warp-level primitives (__shfl_sync → __shfl), and any code that assumes warp size = 32. Run the diff and verify.

🎯 Chapter 15 Summary

ROCm tooling: rocm-smi (GPU monitoring, like nvidia-smi), rocprof (profiling with hardware counters), omniperf (deep per-kernel analysis with roofline modeling — AMD's Nsight Compute equivalent), hipify-perl/clang (CUDA→HIP conversion). Always review the hipify diff for warp-size assumptions.

🧪 Quick Check

Your HIP kernel is running at 30% of peak FP16. What tool tells you if it's memory-bound or compute-bound?

omniperf. It generates a roofline plot showing exactly where your kernel sits relative to the memory bandwidth ceiling and compute ceiling. If your kernel is below the memory bandwidth line, it's memory-bound (optimize memory access). If it's at the compute ceiling, it's compute-bound (use tensor cores or reduce instruction count). rocprof --stats also gives basic metrics, but omniperf is the deep analysis tool.
