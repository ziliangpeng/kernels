1. FlashAttention concept

Standard attention computes softmax(QK^T / √d) @ V by materializing the full S × S attention matrix in HBM. FlashAttention tiles the computation so the full matrix never lives in HBM — only in SMEM/registers. This is both faster (less HBM traffic) and uses less memory (O(S) instead of O(S²)).

Standard vs FlashAttention: Standard: 1. Compute full S = Q @ K^T → (B, H, S, S) in HBM ← O(S²) memory 2. Apply mask + softmax → (B, H, S, S) in HBM 3. Compute O = S @ V → (B, H, S, D) in HBM → Writes S×S matrix to HBM 3 times → bandwidth bottleneck FlashAttention (tiled): For each Q tile (Br rows): Load Q_tile to SMEM For each K,V tile (Bc cols): Load K_tile, V_tile to SMEM Compute partial S = Q_tile @ K_tile^T (in SMEM/registers) Apply mask, accumulate softmax statistics Accumulate O += softmax(S) @ V_tile Store O_tile to HBM → S×S matrix NEVER written to HBM → O(S) memory, much faster

2. Triton attention kernel

@triton.jit
def attention_kernel(q_ptr, k_ptr, v_ptr, o_ptr,
                    scale, stride_qh, stride_kh, stride_vh, stride_oh,
                    Sq: tl.constexpr, Sk: tl.constexpr, D: tl.constexpr,
                    Bc: tl.constexpr, Br: tl.constexpr):
    pid = tl.program_id(0)
    q_off = pid * Br

    # Initialize output and running softmax stats
    m_i = tl.full([Br], -float('inf'), dtype=tl.float32)  # running max
    l_i = tl.zeros([Br], dtype=tl.float32)                     # running sum
    acc = tl.zeros([Br, D], dtype=tl.float32)

    # Load Q tile once (reused across all K,V tiles)
    q = tl.load(q_ptr + q_off * stride_qh + tl.arange(0, Br)[:, None] * stride_qh
                + tl.arange(0, D)[None, :])

    # Loop over K,V tiles
    for kv_off in range(0, Sk, Bc):
        k = tl.load(...)  # load K tile (Bc, D)
        v = tl.load(...)  # load V tile (Bc, D)

        # Compute attention scores: Q @ K^T
        s = tl.dot(q, k.T) * scale  # (Br, Bc) — auto tensor cores

        # Online softmax: update running max and sum
        m_new = tl.maximum(m_i, tl.max(s, axis=1))
        alpha = tl.exp(m_i - m_new)
        p = tl.exp(s - m_new[:, None])
        l_i = l_i * alpha + tl.sum(p, axis=1)
        # Rescale accumulator
        acc = acc * alpha[:, None] + tl.dot(p.to(v.dtype), v)
        m_i = m_new

    # Final normalization
    acc = acc / l_i[:, None]
    tl.store(o_ptr + ..., acc)

3. Why it's fast — tiling Q

The key insight: Q is loaded once per row-tile and reused across all K/V tiles. The S×S attention matrix is never materialized in HBM — it exists only in SMEM/registers as partial scores. This reduces HBM traffic from O(S²) to O(S × D), making attention O(S) in memory instead of O(S²).

The online softmax (updating running max and sum incrementally) is the trick that makes this possible — you don't need the full row to compute softmax, you can accumulate it tile by tile.

🎯 Chapter 19 Summary

FlashAttention in Triton: tile Q (load once, reuse across K/V tiles), compute partial scores in SMEM, use online softmax (running max + sum) to avoid materializing the full S×S matrix. HBM traffic drops from O(S²) to O(S×D). tl.dot uses tensor cores for the QK^T and PV matmuls. This is the kernel pattern used by vLLM, SGLang, and FlashAttention-2/3.

🧪 Quick Check

Why does FlashAttention use O(S) memory instead of O(S²)?

Standard attention materializes the full S×S score matrix QK^T in HBM — O(S²) memory. FlashAttention tiles the computation: it loads a Q row-tile (Br rows), then iterates over K/V column-tiles, computing partial scores in SMEM/registers — the full S×S matrix is never written to HBM. Only the final output O (shape S×D) is written. The online softmax trick (running max + running sum) allows computing softmax incrementally without the full row. Memory: O(Br × Bc) in SMEM + O(S × D) in HBM = O(S).
