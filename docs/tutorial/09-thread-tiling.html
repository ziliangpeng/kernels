1. Problem with SMEM-tiled GEMM

In the SMEM-tiled kernel (ch08), each thread computes one output element. For each output, it reads TILE elements from SMEM As and TILE from SMEM Bs — that's 2×TILE SMEM reads per output. SMEM is fast (~30 cycles), but each read is still a separate instruction.

SMEM-tiled: 1 thread → 1 output element Thread (ty, tx) computes C[row][col]: for k in 0..TILE: sum += As[ty][k] * Bs[k][tx] ← 2 SMEM reads per iteration Each thread does TILE iterations = 2×TILE SMEM reads for 1 output. With TILE=16: 32 SMEM reads for 1 output. SMEM bandwidth is shared across the whole block — this is the bottleneck.

2. Thread tiling — each thread computes a sub-tile

Instead of 1 thread → 1 output, make 1 thread → TM×TN output sub-tile. The thread loads data from SMEM into registers, then reuses it for multiple outputs. This reduces SMEM reads per output.

Thread tiling: 1 thread → TM×TN outputs Thread computes a TM×TN sub-tile of C: ┌────────┐ │c c c c │ TM=2, TN=4 → 8 outputs per thread │c c c c │ └────────┘ For each k: Load A[ty*TM : ty*TM+TM][k] into registers (TM values) Load B[k][tx*TN : tx*TN+TN] into registers (TN values) Compute TM×TN outer products in registers → accumulate to C SMEM reads: TM + TN per k (not 2) Outputs: TM × TN per k Ratio: (TM+TN) / (TM×TN) — for TM=TN=4: 8/16 = 0.5 (vs 2.0 before)

3. Thread-tiled GEMM kernel

__global__ void gemm_thread_tiled(const float* A, const float* B,
                                    float* C, int M, int N, int K) {
    constexpr int BM = 64, BN = 64, BK = 16;
    constexpr int TM = 4, TN = 4;  // each thread computes 4×4 outputs

    __shared__ float As[BM][BK];
    __shared__ float Bs[BK][BN];

    int tx = threadIdx.x, ty = threadIdx.y;
    int row = blockIdx.y * BM + ty * TM;
    int col = blockIdx.x * BN + tx * TN;

    float regC[TM][TN] = {{0.0f}};  // register accumulators
    float regA[TM], regB[TN];  // register cache for one k-slice

    for (int kt = 0; kt < K; kt += BK) {
        // Cooperative load to SMEM (same as before)
        // ... load As[BM][BK] and Bs[BK][BN] ...

        __syncthreads();

        // Compute from SMEM into registers
        for (int k = 0; k < BK; k++) {
            // Load A slice into registers (TM values)
            for (int m = 0; m < TM; m++)
                regA[m] = As[ty * TM + m][k];

            // Load B slice into registers (TN values)
            for (int n = 0; n < TN; n++)
                regB[n] = Bs[k][tx * TN + n];

            // Outer product accumulate to regC
            for (int m = 0; m < TM; m++)
                for (int n = 0; n < TN; n++)
                    regC[m][n] += regA[m] * regB[n];
        }
        __syncthreads();
    }

    // Write results to global memory
    for (int m = 0; m < TM; m++)
        for (int n = 0; n < TN; n++)
            C[(row + m) * N + col + n] = regC[m][n];
}

4. Why this helps

KernelSMEM reads per outputTFLOPS
SMEM-tiled (1 output/thread)2×TILE = 32~5
Thread-tiled (TM=4, TN=4 → 16 outputs/thread)(4+4)/16 = 0.5~8-10
The key win: data loaded from SMEM into registers is reused across TM×TN outputs via outer products. This reduces SMEM bandwidth pressure by ~(TM×TN)/(TM+TN)×. With TM=TN=4, that's 8× less SMEM traffic. Registers are ~30× faster than SMEM and per-thread (no bank conflicts).

🎯 Chapter 09 Summary

Thread tiling: each thread computes a TM×TN sub-tile of C instead of 1 element. Load A/B slices from SMEM into registers, compute outer products in registers. SMEM reads per output drops from 2×TILE to (TM+TN)/(TM×TN) — with TM=TN=4, that's 8× reduction. Registers are per-thread (no bank conflicts) and 30× faster than SMEM. Achieves ~8-10 TFLOPS.

🧪 Quick Check

With TM=4, TN=4, how many SMEM reads does each thread do per k-iteration, and how many outputs does it produce?

Per k-iteration: TM + TN = 8 SMEM reads (4 for A slice + 4 for B slice). These produce TM × TN = 16 output updates (via outer product). So the ratio is 8/16 = 0.5 SMEM reads per output update — vs 2.0 for 1-output-per-thread. That's a 4× reduction in SMEM bandwidth per output, which is why thread tiling gives ~2× speedup.
