1. The key idea: tile and reuse

Instead of each thread independently loading from global memory, load a tile of A and B into shared memory once, then all threads in the block compute from the fast SMEM. This eliminates the redundancy.

Shared memory tiling concept: Divide A and B into tiles of size TILE×TILE. For each output tile C[i][j], iterate over K in TILE-sized chunks: For kt = 0, TILE, 2*TILE, ..., K-TILE: 1. Load A[i][kt:kt+TILE] tile into SMEM (cooperative load) 2. Load B[kt:kt+TILE][j] tile into SMEM (cooperative load) 3. __syncthreads() 4. Each thread computes partial sum from SMEM tiles 5. __syncthreads() (before overwriting SMEM for next tile) Each A/B tile is loaded ONCE from global memory, reused by TILE×TILE threads in the block → amplification reduced ~TILE×.

2. Tiled GEMM kernel

__global__ void gemm_tiled(const float* A, const float* B, float* C,
                           int M, int N, int K) {
    constexpr int TILE = 16;

    // Shared memory tiles
    __shared__ float As[TILE][TILE];
    __shared__ float Bs[TILE][TILE];

    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    float sum = 0.0f;

    // Iterate over K in TILE-sized chunks
    for (int kt = 0; kt < K; kt += TILE) {
        // Cooperative load: each thread loads one element of each tile
        if (row < M && kt + threadIdx.x < K)
            As[threadIdx.y][threadIdx.x] = A[row * K + kt + threadIdx.x];
        if (kt + threadIdx.y < K && col < N)
            Bs[threadIdx.y][threadIdx.x] = B[(kt + threadIdx.y) * N + col];

        // Wait for all threads to finish loading
        __syncthreads();

        // Compute partial sum from SMEM tiles
        for (int k = 0; k < TILE; k++) {
            sum += As[threadIdx.y][k] * Bs[k][threadIdx.x];
        }

        // Wait for all threads to finish computing before overwriting SMEM
        __syncthreads();
    }

    if (row < M && col < N) {
        C[row * N + col] = sum;
    }
}

3. Why this is faster — memory traffic analysis

KernelGlobal loads per outputAmplificationTFLOPS
Naive2 × K~K× (4000×)~0.5
Tiled (TILE=16)2 × K / 16~K/16× (250×)~3
Tiled (TILE=32)2 × K / 32~K/32× (128×)~5
Each tile is loaded once and reused by TILE² threads. With TILE=16, each A and B element is loaded 16× fewer times from global memory. The SMEM tiles are small (16×16×4 = 1KB each) and fast (30 cycles vs 400 for global).

4. The critical __syncthreads() pattern

Two __syncthreads() per tile iteration:
  1. After loading SMEM — before computing (ensure all data is ready)
  2. After computing — before loading next tile (ensure all threads are done reading before overwriting)
Forgetting either one causes a race condition — some threads read stale or partially-overwritten data. This is the #1 bug in tiled kernels.

5. What's still slow

Tiled GEMM bottleneck: each thread does 16 mul-adds per tile, but each mul-add is a separate instruction. The thread is doing scalar work — no vectorization, no tensor cores. Next optimizations: - Thread tiling (ch09): each thread computes a small sub-tile, keeping more data in registers → fewer SMEM accesses - Vectorized loads (ch10): load float4 (4 floats) per instruction - Double buffering (ch11): overlap next tile load with current compute - Tensor cores (ch12): use hardware matrix multiply units (15× faster)

🎯 Chapter 08 Summary

Shared memory tiling: load a TILE×TILE block of A and B into SMEM cooperatively, __syncthreads(), compute partial sums from SMEM, __syncthreads(), repeat for next tile. Each tile is loaded once from global memory, reused by TILE² threads → amplification reduced ~TILE×. Two __syncthreads() per iteration are mandatory (after load, after compute). Achieves ~3-5 TFLOPS.

🧪 Quick Check

Why do you need two __syncthreads() per tile iteration in tiled GEMM?

First __syncthreads() (after load): ensures all threads have finished writing to SMEM before any thread reads. Without it, a fast thread might read a tile element before a slow thread has written it. Second __syncthreads() (after compute): ensures all threads have finished reading SMEM before the next iteration overwrites it. Without it, a slow thread might read from the next tile's data while a fast thread is already loading it. Both are mandatory to prevent race conditions.
