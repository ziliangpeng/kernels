2. MXFP4 — 4-bit floating point

MXFP4 is OCP Microscaling FP4 format: 4-bit floats with a shared 8-bit exponent per block of 32 elements. This allows 2× the throughput of FP8 and 4× of FP16.

MXFP4 layout: Each element: 4 bits (1 sign + 2 mantissa, exponent shared per block) Block scale: 8-bit exponent per 32 elements [e8] [4b][4b][4b]...[4b] ← 32 elements share one exponent ↑ └── 32 × 4-bit values = 16 bytes └── 1 byte shared exponent Total: 17 bytes for 32 values (vs 128 bytes for FP32) = 7.5× compression
MXFP4 is the frontier of LLM inference quantization. DSV4-Flash, Kimi K3, and other frontier models use MXFP4 for weights. Native GFX950 support means no dequant overhead — the matrix cores handle MXFP4 directly.

3. MXFP8 — 8-bit with block scaling

MXFP8 is like FP8 but with per-block scaling factors (every 32 elements share a scale). This gives better precision than per-tensor scaling while keeping the bandwidth savings.

// GFX950 MFMA instructions (AMD's tensor cores)

// Throughput: 2× FP8, 4× FP16

// Using via HIP C++ intrinsics:
__device__ void mfma_f32_16x16x32_f4(
    float result[4],     // 16×16 / 64 lanes = 4 per thread
    uint32_t a,          // packed FP4 (8 values per 32-bit reg)
    uint32_t b,
    float c[4]
);

5. AITER — AMD's Triton kernel library

AITER (AMD Instant Triton Engine Runtime) is a collection of high-performance Triton kernels for LLM workloads on MI300X/MI325X/MI350X. It's AMD's answer to FlashAttention + FlashInfer.

# Install AITER
pip install aiter

# Key kernels:
#   - Attention (MLA, GQA, Gated MLA)
#   - MoE (grouped GEMM, dispatch, combine)
#   - Normalization (RMSNorm, LayerNorm)
#   - Quantization (FP8/INT4 dequant)
#   - Rotary embedding

# Used by vLLM and SGLang on AMD
AITER on GFX950 is the frontier. The DSA sparse MLA kernel you're learning toward (chapter 20) runs on AITER. Non-determinism in AITER on MI350X causes CJK character repetition — a known production issue. Understanding AITER internals is key to debugging production AMD inference.

GFX950 (MI350X) adds native MXFP4 (4-bit, 2× FP8 throughput), MXFP8 (block-scaled FP8), 8 TB/s HBM3e, 288GB HBM. MFMA matrix instructions handle MXFP4/FP8 natively. 🧪 Quick Check

Why does MXFP4 give 2× throughput over FP8 on GFX950?

Because MXFP4 elements are 4 bits vs 8 bits for FP8. The matrix core processes a fixed number of bits per instruction. With 4-bit elements, it can process 2× more values per instruction compared to 8-bit. The shared exponent (1 per 32 elements) adds minimal overhead — 8 bits / 32 elements = 0.25 bits per element. So effective precision is 4.25 bits but throughput is 2× FP8.
