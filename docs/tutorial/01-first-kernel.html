1. Anatomy of a CUDA program

A CUDA program has two parts: host code (runs on CPU) and device code (runs on GPU). The flow is always:

CUDA program flow: CPU (host): GPU (device): ─────────── ──────────── 1. cudaMalloc(&d_a, size) → allocate d_a in global memory 2. cudaMemcpy(d_a, h_a, H→D) → copy data to GPU 3. kernel<<<grid,block>>>(d_a) → launch kernel (ASYNC) (CPU continues...) [GPU runs kernel] 4. cudaDeviceSynchronize() ← wait for GPU to finish 5. cudaMemcpy(h_c, d_c, D→H) ← copy result back 6. cudaFree(d_a) → free GPU memory

2. The kernel function — __global__

A kernel is a function that runs on the GPU. It's marked with __global__ and is called from the CPU.

// __global__ = "this function runs on GPU, called from CPU"
__global__ void vector_add(const float* a, const float* b, float* c, int n) {
    // Each thread computes ONE element of c
    int tid = threadIdx.x + blockIdx.x * blockDim.x;

    // Bounds check — make sure we don't go past the array
    if (tid < n) {
        c[tid] = a[tid] + b[tid];
    }
}

3. Thread indexing — finding your global ID

Every thread needs to know "which element am I responsible for?" This is computed from the built-in variables:

// Built-in variables available in every kernel:
threadIdx.x   // thread index within block (0..blockDim.x-1)
blockIdx.x    // block index within grid (0..gridDim.x-1)
blockDim.x    // threads per block
gridDim.x     // blocks per grid

// Global thread ID (1D):
int global_tid = blockIdx.x * blockDim.x + threadIdx.x;

// Example: gridDim=4, blockDim=256
// Block 0: threads 0..255
// Block 1: threads 256..511
// Block 2: threads 512..767
// Block 3: threads 768..1023
Computing global thread ID: Grid (4 blocks): ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ Block 0 │ │ Block 1 │ │ Block 2 │ │ Block 3 │ │ threads │ │ threads │ │ threads │ │ threads │ │ 0..255 │ │ 256..511 │ │ 512..767 │ │ 768..1023 │ └──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘ For a thread in Block 2 with threadIdx.x = 5: global_tid = blockIdx.x * blockDim.x + threadIdx.x = 2 * 256 + 5 = 517 This thread handles element c[517].
Always bounds-check! If n isn't a multiple of blockDim × gridDim, some threads will compute IDs beyond the array. Without if (tid < n), they'll write out of bounds → memory corruption.

4. Launching the kernel

// Problem: add two arrays of n=1,000,000 elements
int n = 1000000;

// Choose block size (typically 128 or 256)
int blockDim = 256;

// Compute grid size to cover all elements
int gridDim = (n + blockDim - 1) / blockDim;  // ceiling division

// Launch!
vector_add<<<gridDim, blockDim>>>(d_a, d_b, d_c, n);

// gridDim = ceil(1000000 / 256) = 3907 blocks
// Total threads = 3907 * 256 = 1,000,192 (slightly more than n)
// The extra 192 threads hit the bounds check and do nothing.
Ceiling division pattern: (n + block - 1) / block is the standard way to compute "how many blocks do I need?" It rounds up so all elements are covered.

5. Full working program

#include <stdio.h>
#include <cuda_runtime.h>

// ── Kernel ───────────────────────────────────────────
__global__ void vector_add(const float* a, const float* b, float* c, int n) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid < n) {
        c[tid] = a[tid] + b[tid];
    }
}

// ── Host code ────────────────────────────────────────
int main() {
    int n = 1000000;
    size_t bytes = n * sizeof(float);

    // 1. Allocate host memory
    float *h_a = (float*)malloc(bytes);
    float *h_b = (float*)malloc(bytes);
    float *h_c = (float*)malloc(bytes);

    // Initialize
    for (int i = 0; i < n; i++) { h_a[i] = 1.0f; h_b[i] = 2.0f; }

    // 2. Allocate device memory
    float *d_a, *d_b, *d_c;
    cudaMalloc(&d_a, bytes);
    cudaMalloc(&d_b, bytes);
    cudaMalloc(&d_c, bytes);

    // 3. Copy data to GPU
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, h_b, bytes, cudaMemcpyHostToDevice);

    // 4. Launch kernel
    int block = 256;
    int grid = (n + block - 1) / block;
    vector_add<<<grid, block>>>(d_a, d_b, d_c, n);

    // 5. Wait and copy back
    cudaDeviceSynchronize();
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);

    // 6. Verify
    for (int i = 0; i < n; i++) {
        if (h_c[i] != 3.0f) { printf("FAIL at %d\n", i); return 1; }
    }
    printf("PASS\n");

    // 7. Free
    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    free(h_a); free(h_b); free(h_c);
    return 0;
}

6. Compiling with nvcc

# Save as vector_add.cu, compile with nvcc:
nvcc -o vector_add vector_add.cu

# With optimizations and architecture flag:
nvcc -O3 -arch=sm_80 -o vector_add vector_add.cu

# Run
./vector_add
-arch=sm_XX matters: Different GPU architectures have different features. sm_80 = A100, sm_90 = H100, sm_100 = B100. Use the architecture that matches your GPU. If you don't specify, nvcc compiles for an older architecture and may miss features.

🎯 Chapter 01 Summary

A CUDA program: allocate GPU memory (cudaMalloc), copy data to GPU (cudaMemcpy H→D), launch kernel (kernel<<<grid, block>>>), wait (cudaDeviceSynchronize), copy result back (cudaMemcpy D→H), free. The kernel uses threadIdx + blockIdx × blockDim to find its global ID. Always bounds-check. Compile with nvcc.

🧪 Quick Check

You have n=1000 elements and blockDim=256. How many blocks do you need?

ceil(1000 / 256) = 4 blocks. Using the ceiling division formula: (1000 + 256 - 1) / 256 = 1255 / 256 = 4. Total threads = 4 × 256 = 1024. The extra 24 threads (IDs 1000-1023) hit the bounds check (if (tid < n)) and do nothing. This is normal and expected.
